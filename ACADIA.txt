# PLATFORM OVERVIEW

## What is ACADIA?

ACADIA is an **offline-first educational platform** designed specifically for Ethiopian students. It provides comprehensive learning materials for High School (Grades 9-12) and University students, with content delivered dynamically without requiring app updates.

## Key Features

- **50 Screens** of rich educational content
- **19 Subjects** with 6 content types per chapter
- **Offline-First Architecture** - Download once, study anywhere
- **Interactive Learning** - Quizzes, exams, flashcards with instant feedback
- **University Entrance Exam Preparation** - Past papers, practice questions, study schedules
- **ACADIA AI** - Offline AI assistant for personalized tutoring
- **Secure Payments** - 5 Ethiopian payment methods with admin approval
- **Admin Dashboard** - Complete content and user management
- **Multi-Language Support** - English, Amharic, Afaan Oromoo

## Target Users

### Students
- High School (Grades 9-12, Natural & Social Science streams)
- University (Freshman to Senior, all generations)
- Entrance Exam candidates (Grade 11-12)

### Admins
- Content managers
- Payment approvers
- User managers
- Analytics viewers

# CORE PHILOSOPHY

## Design Principles

### 1. Offline-First
> "Ethiopian students deserve education without internet dependency."

- All content downloadable for offline access
- Local database (Isar) for progress tracking
- No internet required after initial content download
- Automatic sync when online

### 2. Content Separated from Code
> "Change content without rebuilding the app."

- Educational content in GitHub
- App configuration in Firebase
- Code is only the learning engine
- No APK updates for content changes

### 3. Zero Cost Philosophy
> "Education should be accessible without server costs."

- Firebase free tier (10,000 users)
- GitHub free storage
- ImgBB free image hosting
- YouTube free video hosting

### 4. One Device, One Account
> "Your account is tied to your device for security."

- Single device per account
- Auto-logout on new device login
- Session management with Firebase
- Manual logout required for device switch

### 5. Simple Color Palette
> "Clean, professional, distraction-free."

- Navy Blue (#093C5D) - Primary
- White - Backgrounds
- Black - Text
- Dark Mode - Compatible

### Content Delivery Flow

```
Admin Uploads Content
        ↓
1. Push to GitHub Repository
   - Update metadata.json
   - Update version.json
   - Upload new files
   - Create GitHub Release (large files)
        ↓
2. App Checks for Updates
   - Daily check
   - Compare version.json
   - New version detected
        ↓
3. App Fetches Updated Content
   - Download new metadata
   - Update local Isar database
   - Show new content
        ↓
4. User Downloads Content
   - Taps DOWNLOAD button
   - Fetches from GitHub Release
   - Saves to private storage
   - Shows OFFLINE badge
        ↓
5. User Accesses Content Offline
   - No internet needed
   - All content available
   - Progress tracked locally
   - Sync when online
```

# AUTHENTICATION & SECURITY

## One Device, One Account System

### How It Works

```
User Logs In (Device A)
        ↓
Device ID Stored with User Account
        ↓
User Tries to Login (Device B)
        ↓
Check Device ID
    ├── Same Device → Login Success
    └── Different Device → Error: "Account already logged in on another device"
            ↓
        Option: "Logout from other device?"
            ↓
        User Confirms
            ↓
        Device A Logged Out
        ↓
        Device B Logged In
```

### Implementation

```dart
class AuthService {
    Future<void> signIn(String email, String password) async {
        // 1. Authenticate with Firebase
        UserCredential result = await FirebaseAuth.instance
            .signInWithEmailAndPassword(email: email, password: password);
        
        // 2. Get device ID
        String deviceId = await getDeviceId();
        
        // 3. Check Firestore for existing device
        DocumentSnapshot doc = await FirebaseFirestore.instance
            .collection('users')
            .doc(result.user!.uid)
            .get();
        
        String? storedDeviceId = doc.data()?['deviceId'];
        
        // 4. Device mismatch check
        if (storedDeviceId != null && storedDeviceId != deviceId) {
            // Show dialog: Account logged in on another device
            bool confirm = await showDialog(
                context: context,
                builder: (context) => AlertDialog(
                    title: Text('Device Conflict'),
                    content: Text('This account is logged in on another device. Logout from other device?'),
                    actions: [
                        TextButton(
                            onPressed: () => Navigator.pop(context, false),
                            child: Text('Cancel'),
                        ),
                        TextButton(
                            onPressed: () => Navigator.pop(context, true),
                            child: Text('Logout Other Device'),
                        ),
                    ],
                ),
            );
            
            if (confirm) {
                // Logout other device
                await logoutOtherDevice(result.user!.uid);
                // Update device ID
                await updateDeviceId(result.user!.uid, deviceId);
            } else {
                throw Exception('Please logout from the other device first.');
            }
        } else {
            // Update device ID
            await updateDeviceId(result.user!.uid, deviceId);
        }
        
        // 5. Continue login
        await handleUserAuth(result);
    }
    
    Future<void> logoutOtherDevice(String userId) async {
        // Force logout other device via FCM
        String? fcmToken = await getFCMToken();
        if (fcmToken != null) {
            await FirebaseMessaging.instance.send(
                message: RemoteMessage(
                    data: {
                        'type': 'force_logout',
                        'userId': userId,
                    },
                    token: fcmToken,
                ),
            );
        }
        
        // Clear session in Firestore
        await FirebaseFirestore.instance
            .collection('users')
            .doc(userId)
            .update({
                'activeSession': false,
                'deviceId': null,
            });
    }
}
```

# ACADIA AI ASSISTANT

## Overview

ACADIA AI is an offline-first AI assistant that helps students with questions, exams, and tutoring using downloaded academic content.

## Features

### 1. Question Answering
- Students ask questions in natural language
- AI searches through downloaded content
- Provides relevant answers with explanations
- Cites sources (subject, chapter, unit)

### 2. Exam Preparation
- Analyzes weak areas
- Generates practice questions
- Creates personalized study plans
- Recommends specific units to review

### 3. Tutoring
- Explains concepts in simple terms
- Provides examples from downloaded content
- Offers step-by-step solutions
- Adapts explanation level based on progress

### 4. Progress Tracking
- Monitors improvement over time
- Identifies knowledge gaps
- Suggests next topics to study
- Tracks study streak

### 5. Personalized Recommendations
- Based on quiz/exam performance
- Focuses on weak subjects
- Recommends video, notes, or flashcards
- Adjusts difficulty level

### 6. Offline First
- Works without internet
- Uses downloaded content
- No external API calls
- Private and secure

## How It Works

```
User Asks Question
        ↓
AI Analyzes Question
        ↓
Searches Local Content
    ├── Flashcards (quickest)
    ├── Quiz Questions
    ├── PDFs (text extraction)
    └── Video Transcripts
        ↓
Finds Relevant Content
        ↓
Generates Response
    ├── Answer
    ├── Explanation
    ├── Example
    └── Source Reference
        ↓
Returns to User
        ↓
User Provides Feedback
    ├── Helpful → Save to Knowledge Base
    └── Unhelpful → Refine Search
```

## Implementation

```dart
class AcadiaAI {
    final IsarLocalDatabase db;
    final UserProgress progress;
    
    // Core AI Functions
    Future<String> askQuestion(String question) async {
        // 1. Analyze question intent
        QuestionIntent intent = await analyzeIntent(question);
        
        // 2. Search local content
        List<SearchResult> results = await searchContent(question);
        
        // 3. Generate response
        String answer = await generateAnswer(question, results);
        
        // 4. Save context
        await saveContext(question, answer);
        
        return answer;
    }
    
    // Search Functions
    Future<List<SearchResult>> searchContent(String query) async {
        List<SearchResult> results = [];
        
        // Search flashcards (fastest)
        results.addAll(await searchFlashcards(query));
        
        // Search quiz questions
        results.addAll(await searchQuizzes(query));
        
        // Search PDFs (if downloaded)
        if (await hasDownloadedPDFs()) {
            results.addAll(await searchPDFs(query));
        }
        
        // Rank by relevance
        results.sort((a, b) => b.relevance.compareTo(a.relevance));
        
        return results;
    }
    
    // Study Recommendations
    Future<List<String>> recommendStudyTopics() async {
        // Get weak areas from results
        List<WeakArea> weakAreas = await getWeakAreas();
        
        // Generate recommendations
        List<String> recommendations = [];
        for (var weak in weakAreas) {
            recommendations.add(
                "Review ${weak.subject} Unit ${weak.unit}: ${weak.topic} "
                "(Score: ${weak.score}%)"
            );
        }
        
        return recommendations;
    }
    
    // Generate Practice Questions
    Future<List<Question>> generatePracticeQuestions() async {
        // Identify weak areas
        List<WeakArea> weakAreas = await getWeakAreas();
        
        // Generate questions for weak areas
        List<Question> questions = [];
        for (var weak in weakAreas) {
            questions.addAll(await generateQuestionsForTopic(
                weak.subject,
                weak.unit,
                weak.topic,
                count: 5,
            ));
        }
        
        return questions;
    }
}
```

### Firestore Security Rules
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users collection
    match /users/{userId} {
      allow read: if request.auth != null && request.auth.uid == userId;
      allow write: if request.auth != null && request.auth.uid == userId;
      allow read: if request.auth != null && 
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
    }
    
    // Settings collection
    match /settings/{doc} {
      allow read: if true;
      allow write: if request.auth != null && 
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
    }
    
    // Notifications collection
    match /notifications/{doc} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && 
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
    }
    
    // Payments collection
    match /payments/{doc} {
      allow read: if request.auth != null && 
        (request.auth.uid == resource.data.userId || 
         get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true);
      allow write: if request.auth != null && 
        (request.auth.uid == resource.data.userId ||
         get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true);
    }
  }
}
```
