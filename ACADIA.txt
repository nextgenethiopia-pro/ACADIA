# ACADIA V1.0.0 — COMPLETE DESCRIPTION

---

## 1. APP OVERVIEW

ACADIA is a digital education platform built for Ethiopian students. It covers High School (Grades 9–12, Natural and Social Science streams) and University (Freshman and Senior, all generations and technology institutes).

**Six content formats** are delivered per chapter: **Video, Short Note, Quiz, Exam, Flashcard, and Past Paper**.

The app is fully **offline-first**. All content files — videos, PDFs, quizzes, exams, flashcards, past papers — are hosted on **Internet Archive**. The app downloads them once and stores them in private app storage. Students study without needing an internet connection after the initial download.

**Firebase** handles authentication (email/password with verification) and the Firestore database (user profiles, payments, notifications, content metadata). **GitHub Pages** hosts a lightweight configuration file so content can be updated without releasing a new APK.

The primary color is **`#111844`** (deep navy blue).

## 2. USER DATA & PERMANENT PATH

Every user's complete academic path is saved **permanently** in Firebase Firestore and locally in SharedPreferences. The path cannot be changed after registration.

**Data saved:**

| Field | Example Value |
|-------|---------------|
| `school_level` | `high-school` or `university` |
| `grade` | `9`, `10`, `11`, `12` |
| `stream` | `natural_science` or `social_science` |
| `generation` | `1st Generation`, `2nd Generation`, `3rd Generation`, `4th Generation`, `Technology Institutes` |
| `university` | Full university name (e.g., `AAU - Addis Ababa University`) |
| `university_year` | `freshman` or `senior` |
| `semester` | `1` or `2` |
| `track` | `pre_engineering` or `other_natural_science` |
| `path_status` | `permanently_locked` |

All selections — from the first academic path choice down to the final university name or stream — are recorded and permanently locked.

## 3. PROGRESS TRACKING (LOCAL)

All user progress is tracked **locally** in the app's SQLite database and displayed for every user in the **Progress Tab**. Firebase syncs progress when a connection is available so data can be restored on a new device.

**Tracked data:**

| Metric | Description |
|--------|-------------|
| Total study time | Accumulated hours across all subjects |
| Lessons completed | Count of videos, PDFs, and content marked done |
| Quizzes passed | Count of quizzes with score ≥ 60% |
| Average score | Average percentage across all quizzes and exams |
| Current streak | Consecutive days of activity |
| Longest streak | Best consecutive day run |
| Downloaded content | Number of items and total storage used |
| Subject progress | Per-subject completion percentage |
| Weekly activity | Hours studied per day (Mon–Sun bar chart) |

**Achievements (4 badges):**

| Badge | Requirement | Color |
|-------|------------|-------|
| First Steps | Complete first content item | Blue |
| Perfect Week | 7-day study streak | Orange |
| Quiz Master | Pass 10 quizzes | Gold |
| Dedicated | 50 hours of study | Purple |

Unlocked badges show normally. Locked badges show a lock icon with the requirement text.

## 4. SUBJECTS & CHAPTER LOCKING

### Subjects are always visible
All subjects for the user's academic path are displayed in the Subjects tab. Students can browse every subject without purchasing a package.

### Chapters are locked until purchase
Each chapter shows a lock overlay until the user purchases their grade package. **When purchased, all chapters unlock immediately** — no prerequisites, no sequential unlocking. The lock overlay shows the package name, price, and an "UNLOCK NOW" button that navigates to the payment screen.

### Package validity
Each grade package is valid for **one year** from admin approval date. After expiry, chapters lock again and the user must repurchase.

## 5. CONTENT SYSTEM

### 6 Content Types Per Chapter

| Type | Format | Player/Viewer |
|------|--------|---------------|
| **Video** | .mp4 | Native video player with speed control (0.5x–2.0x), play/pause, rewind/forward 10s, volume, progress scrubbing |
| **Short Note** | .pdf | PDF viewer with pinch-to-zoom, page navigation |
| **Quiz** | .json | MCQ with A/B/C/D options, two feedback modes |
| **Exam** | .json | Timed MCQ with pause, question grid, auto-finish |
| **Flashcard** | .json | Flip animation, "Got it" / "Didn't know" tracking |
| **Past Paper** | .json | MCQ from previous exams, timed |

### Content Storage & Delivery

| Layer | Technology |
|-------|-----------|
| All content files (videos, PDFs, JSONs) | **Internet Archive** (free, unlimited) |
| Content metadata (titles, subjects, chapters, URLs) | **Firebase Firestore** |
| Content update config | **GitHub Pages** (single JSON file) |
| Offline storage | **SQLite** + app private directory |

### Download Flow
1. Student sees content slot with DOWNLOAD button and file size.
2. Taps download → progress indicator shows.
3. File saved to app private storage.
4. SQLite records the download (content_id, local_path, file_size, date).
5. Button changes to PLAY/VIEW with green "OFFLINE" badge.
6. All playback is from the local file — no streaming.

## 6. QUIZ & EXAM BEHAVIOR

### No Submit Button
There is no separate "Submit" step. Students answer questions and navigate. Results are calculated automatically and shown at the end.

### Quiz — Two Feedback Modes

**Option 1: Immediate Feedback**
- Student taps an answer choice.
- **Correct** → choice turns green.
- **Wrong** → choice turns red, correct answer highlights green.
- A "Show Explanation" button appears. Tapping it reveals the explanation.
- Student taps "Next" to continue.
- At the end, sees full result with all answers and explanations.

**Option 2: Review at End**
- Student answers all questions without immediate feedback.
- At the end, sees every answer marked correct (green) or wrong (red) with explanation for each.

### Exam — Same as Quiz
The exam follows the same pattern as the quiz. A countdown timer runs. When time expires or all questions are answered, the result screen appears. Students can pause the timer; while paused, the question area is hidden.

| AWASH BANK | 01320500140900 | FIRAOL TADESA |

### Payment Flow
1. User selects their grade package (auto-detected from academic path).
2. Chooses payment method.
3. Makes payment to the displayed account.
4. Uploads receipt screenshot (gallery or camera).
5. Enters account number and transaction reference.
6. Taps "CONFIRM PAYMENT" — status set to "pending".
7. Telegram bot sends admin a notification with all details.
8. Admin reviews in Payment Approval screen.
9. Admin approves → package unlocked for 1 year → notification sent to user.
10. Admin rejects → reason required → notification sent.

### Payment History
- Filter by status: All, Pending, Approved, Rejected
- Search by package or date
- Each payment shows amount, method, status, date
- Rejected payments show reason in red box
